# Project Working Rules

These instructions apply to all work in this project.

## Git rules

- Do not create a new Git branch.
- Do not create Git commits.
- Make requested changes directly in the current working directory.
- Leave all changes uncommitted so the project owner can review them first.

## Beginner-friendly code

The project owner is learning HTML, CSS, and JavaScript. Write code that is easy
to read, understand, edit, and learn from, even when that makes the files longer.

- Prefer clear, descriptive class names and variable names.
- Format HTML with consistent indentation and one logical element per line.
- Format CSS with one property per line. Do not compress CSS rules onto one line.
- Organize CSS into clearly labeled sections, such as navigation, hero, cards,
  footer, and responsive styles.
- Add short comments before important sections and around code whose purpose may
  not be obvious to a beginner.
- Prefer straightforward HTML, CSS, and JavaScript over clever shortcuts.
- Avoid unnecessary abstractions, complex selectors, terse syntax, and heavily
  nested expressions.
- In JavaScript, use small functions that each do one clearly named task.
- Explain any important or unfamiliar technique in a nearby comment.
- Preserve accessibility with semantic HTML, useful alternative text, visible
  focus states, and clear labels.
- When handing off a change, briefly explain which files changed and what the
  main sections do in beginner-friendly language.
